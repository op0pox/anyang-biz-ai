# 안양 상권 나침반 — 안양시 소상공인 지원 우선순위 AI

2026년 안양시 공공데이터·AI 활용 대학생 경진대회 출품작.

행정동 × 업종 매출 예측 회귀 모델을 기반으로, 안양시청이 소상공인 지원 예산·정책을
어느 행정동에 우선 배정할지 판단할 수 있도록 돕는 행정 의사결정 지원 AI입니다.
동시에 지역 기반 유리 업종 추천, AI 정책분석 리포트 자동생성 기능을 제공합니다.

## 기존 서비스 대비 차별화 포인트

이미 소상공인365(중기부·소진공), 오픈업(핀다), 나이스비즈맵, 서울시 골목상권분석서비스 등
"상권분석 + 매출추정" 서비스가 존재합니다. 이 프로젝트는 다음 3가지로 차별화합니다.

1. **안양시 전용 데이터 융합** — 안양시가 직접 발행한 주민등록인구 통계 등을 명시적으로
   결합해, 전국 범용 서비스와 달리 안양시 행정에 바로 활용할 수 있도록 설계했습니다.
2. **업종 역(逆)추천** — 기존 서비스는 사용자가 업종을 직접 선택해야 합니다. 이 서비스는
   행정동 데이터를 기반으로 그 지역에 유리한 업종을 먼저 추천합니다.
3. **AI 정책 리포트 자동생성** — 기존 서비스는 숫자·그래프만 제공합니다. 이 서비스는 LLM이
   "왜 이 지역/업종의 지원 우선순위가 높은지"를 사람이 읽는 문장으로 설명합니다.

| 항목 | 소상공인365 / 오픈업 / 나이스비즈맵 | 안양 상권 나침반 |
| --- | --- | --- |
| 타깃 | 개인 창업자 | 안양시 정책담당자 + 창업자 |
| 업종 선택 | 사용자가 직접 선택 | 지역 기반 유리 업종 추천 |
| 결과물 | 숫자·그래프 | 숫자·그래프 + AI 서술형 정책 리포트 |
| 지역 데이터 | 전국 범용 | 안양시 발행 데이터 명시적 융합 |

## 실행 방법

```bash
# 1) 가상환경 준비 (이미 venv-anyang이 있다면 생략)
python3 -m venv venv-anyang
source venv-anyang/bin/activate

# 2) 의존성 설치
pip install -r requirements.txt

# 3) (실제 데이터가 없다면) 가상 데이터 생성 — 파이프라인 검증용
python scripts/make_sample_data.py

# 4) 웹앱 실행
streamlit run app/app.py
```

브라우저에서 `http://localhost:8501` 접속 → 홈 화면에서 서비스 소개 확인 →
사이드바 또는 홈 화면 버튼으로 "매출예측·업종추천 / 지원우선순위 / AI리포트" 페이지 이동.

## 실제 데이터로 교체하는 방법

`data/raw/` 폴더에 아래 표의 stem 이름으로 파일을 넣으면 대부분 코드 수정 없이 동작합니다.
확장자는 `.csv` / `.xlsx` / `.xls` 중 무엇이든 자동으로 인식합니다. (심볼릭 링크도 가능 —
대용량 원본 파일을 복사하지 않고 `ln -s <원본경로> data/raw/<stem>.csv`로 연결해도 됩니다.)

| stem (파일명, 확장자 제외) | 데이터셋 | 출처 | 비고 |
| --- | --- | --- | --- |
| `card_sales` | 카드 소비 데이터 | [경기데이터드림](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=7Y02TF04H1WUB55Q4IZL35052374&infSeq=1) | 행정동×업종별 매출 — 모델 타깃 변수. 월별로 여러 파일에 나뉘어 있어도(`card_sales_202601.csv`, `card_sales_202602.csv`, ...) 자동으로 전부 합산됩니다. **실제 배포 스키마는 컬럼명이 코드화(`admi_cty_no`, `card_tpbuz_nm_1`, `amt`, `cnt`)되어 있어 키워드 매칭이 불가능** — `data_loader.py`가 이 스키마를 자동 감지해, `stores` 데이터의 행정동코드↔행정동명 매핑으로 행정동을 복원합니다. 이 코드-이름 매핑 때문에 **`stores` 데이터가 먼저 있어야** `card_sales`를 정상적으로 읽을 수 있습니다 |
| `stores` | 소상공인시장진흥공단 상가(상권)정보 | [data.go.kr](https://www.data.go.kr/data/15083033/fileData.do) | 업종별 경쟁점포수(밀집도) 피처 + 카드소비 데이터의 행정동코드 매핑 참조표로도 사용됨. 인증키 불필요. 전국/도 단위 대용량 파일이어도 필요한 컬럼만 읽어(`usecols`) 안양시로 필터링하므로 그대로 둬도 됨 |
| `floating_population` | 유동인구_안양시 | [경기데이터드림](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=XRWQQSD1QA5NTR3I38OY36737401&infSeq=1) | **File 다운로드 없음, OPEN API 전용.** `GG_OPEN_API_KEY` 환경변수 설정 시 자동 수집. 로컬에 `data/raw/floating_population.csv` 캐시가 있으면 그것을 우선 사용. 구 단위(만안구/동안구)로만 제공되어 같은 구의 행정동들은 값이 동일하게 들어가는 한계가 있음 |
| `resident_population` | 경기도 안양시_주민등록인구 통계정보 | [data.go.kr](https://www.data.go.kr/data/3036724/fileData.do) | **안양시 직접 발행 데이터 — 공공데이터 활용 가산점용.** 안양시가 실제 배포하는 파일은 행정동 단위 표가 아니라 "안양시 / -만안구 / -동안구" 구 단위만 있는 "세대 및 인구" 통계표(병합 셀 xlsx)라, `_load_resident_population_pivot_table()`이 이를 자동 감지해 구 총인구를 그 구에 속한 모든 행정동에 동일 배분합니다(유동인구와 같은 구 단위 한계) |
| `bus_stops` | 전국버스정류소표준데이터 | [data.go.kr](https://www.data.go.kr/data/15096280/standard.do) | 대중교통 접근성 피처. 파일 다운로드 방식, 인증키 불필요 |

실제 파일의 컬럼명이 예상과 크게 다르면 `src/config.py`의 `COLUMN_HINTS` 딕셔너리에
키워드만 추가/수정하면 됩니다 (컬럼명을 하드코딩하지 않고 부분 문자열 매칭으로 탐색).
단, `card_sales`의 코드화된 스키마와 `resident_population`의 피벗 통계표처럼 컬럼명
매칭 자체가 불가능한 실제 데이터는 `data_loader.py`에 전용 파싱 로직으로 처리했습니다.

### 업종 분류 체계가 다른 두 데이터셋을 합치는 방법

카드소비 데이터(업종 9종: 음식/소매유통/생활서비스/여가오락/학문교육/의료건강/공연전시/
미디어통신/공공기업단체)와 상가정보(업종 10종: 음식/소매/숙박/교육/수리개인/과학기술/
보건의료/예술스포츠/시설관리임대/부동산)는 서로 다른 업종 분류 체계를 씁니다. 그대로 두면
"소매"(상가정보)와 "소매/유통"(카드소비)이 다른 업종으로 취급되어 경쟁점포수와 매출이
같은 업종으로 조인되지 않습니다. `config.py`의 `STORE_TO_CARD_CATEGORY_MAP`이 상가정보
업종명을 카드소비 업종명 체계로 정렬하는 근사 매핑표입니다 — 두 체계가 1:1 대응하지 않아
다대일 매핑이며 완벽하지 않다는 점을 감안해주세요 (예: "예술·스포츠"와 "숙박"이 둘 다
"여가/오락"으로 매핑됨).

### 유동인구 OPEN API (경기데이터드림) 사용법

`data/raw/floating_population.csv` 캐시가 없으면 `GG_OPEN_API_KEY` 환경변수로
서비스 `TBDASANALSGALLERYT214117`(`src/config.py`의 `GG_OPEN_API_SERVICE_NAME`,
확인된 실제 서비스명)를 자동 호출합니다. 1회 호출 최대 1,000건 제한이 있어
`_fetch_floating_population_from_api()`가 페이지네이션합니다.

**데이터 특성 참고**: 이 API 응답은 구(CTY_NM) × 시간대(TIME_CD) × 내/외국인
(FORN_GB) × 성별·5세 연령대(M_10_CNT~F_70_CNT) 단위로 잘게 쪼개진 **다년간의
일별 누적 통계**라 전체가 21만 건이 넘습니다. 우리는 만안구/동안구의 상대적
유동인구 수준만 필요하므로 전체를 다 받지 않고 `GG_OPEN_API_MAX_PAGES`(기본
20페이지 = 2만 건)만큼만 대표 표본으로 가져와 시간대별 합계로 집계합니다. 절대적인
"오늘의 유동인구" 수치가 아니라 여러 날짜가 섞인 표본 기반 상대 비교치라는 점을
감안해주세요. `_parse_gg_floating_population_schema()`가 이 스키마를 전용으로
파싱합니다(컬럼명이 전부 영문 코드라 일반 키워드 매칭 대상이 아님).

### 버스정류소 OPEN API (국토교통부 TAGO) 사용법

`data/raw/bus_stops.csv` 캐시 파일이 없으면 `BUS_API_KEY` 환경변수로 국토교통부
TAGO 버스정류소정보조회 서비스(`getCtyCodeList`로 안양시 도시코드 조회 →
`getSttnNoList`로 정류소 목록 페이지네이션 수집)를 자동 호출합니다. `.env`에
`BUS_API_KEY=발급받은키`를 등록하면 됩니다 — 공공데이터포털이 주는 "Encoding"/
"Decoding" 키 둘 중 무엇을 넣어도 자동 판별해서 처리합니다.

**알려진 데이터 품질 이슈**: 이 API는 도시코드(cityCode)로 조회해도 인접 시
(광명·군포·의왕·부천·서울 일부)의 정류소가 다수 섞여 나옵니다(TAGO의 행정구역
경계 데이터가 완벽하지 않음 — 실제로 "광명시보건소", "군포보건소", "의왕시청",
"서울구치소" 등이 안양시 도시코드 응답에 포함되어 있었습니다). 이미 주소 기반으로
정확히 필터링된 상가정보(stores) 데이터의 실제 위경도 범위로 재필터링해 대부분
걸러내지만(1214건 → 761건), 안양시와 바로 맞닿은 경계 지역 정류소 일부(예: 서울
경계의 "관악역")는 여전히 섞여 있을 수 있습니다 — 정확한 행정동 경계 폴리곤 없이
좌표 범위만으로 거르는 방식의 한계입니다.

## 모델 개요

- **알고리즘**: `RandomForestRegressor` (scikit-learn) — 해석이 쉽고 `feature_importances_`로
  "왜 이런 예측이 나왔는지"를 설명할 수 있어 채택.
- **타깃**: 행정동×업종 조합의 매출금액(카드 소비 데이터 집계). 소수의 대형 점포(백화점 등)가
  있는 조합이 나머지보다 한두 자릿수 더 커서 분포가 심하게 치우쳐 있어, `log1p`로 압축한
  값을 학습 타깃으로 쓰고 예측/평가 시 `expm1`로 원래 금액 스케일로 되돌립니다.
- **피처**: 경쟁점포수, 유동인구(시간대 가중 합산), 거주인구, 버스정류장 접근성(반경 300m).
- **지원 우선순위 스코어**: 예측 매출 수준(45%) + 경쟁 강도(30%) + 유동인구 대비 매출 효율(25%)을
  0~100점으로 정규화. 점수가 높을수록 소상공인 지원 필요도가 높다고 판단.
- 실제 안양시 카드소비·상가정보 데이터(2026년 1~3분기, 31개 행정동) 기준 R² 약 0.28,
  가상 데이터 단계에서는 파이프라인이 끝까지 정상 동작하는지 확인하는 용도로 RMSE/R² 수치
  자체는 의미가 없습니다.

## 알려진 한계

- 유동인구 데이터가 구(만안구/동안구) 단위로만 제공되어, 같은 구에 속한 행정동들은
  유동인구 피처값이 동일하게 들어갑니다. 또한 원본이 여러 해에 걸친 일별 누적
  통계라 전체(21만여 건)를 다 받지 않고 대표 표본(기본 2만 건)만 집계하므로,
  절대적인 "현재" 수치가 아니라 표본 기반 상대 비교치로 해석해야 합니다.
- 안양시가 배포하는 주민등록인구 통계도 "세대 및 인구" 표는 구 단위까지만 있어(행정동별
  상세 표는 별도 미확보), 유동인구와 같은 방식으로 구 총인구를 행정동에 동일 배분했습니다.
- 카드소비 데이터와 상가정보 데이터의 업종 분류 체계가 달라 `STORE_TO_CARD_CATEGORY_MAP`으로
  근사 매핑했습니다 (위 "업종 분류 체계가 다른 두 데이터셋을 합치는 방법" 참고).
- 버스정류소 API(TAGO)는 행정구역 경계 데이터가 정확하지 않아 인접 시 정류소가 일부
  섞여 들어올 수 있습니다 (위 "버스정류소 OPEN API 사용법"의 알려진 이슈 참고).
- 개업일자/폐업 이력 데이터가 없어 "폐업 예측"이 아닌 "매출 예측 + 업종 추천 + 지원
  우선순위"로 문제를 재정의했습니다.
- 표본이 31개 행정동 × 9개 업종(279개 조합)으로 크지 않아, 모델 성능(R²)은 참고용이며
  피처 중요도·업종 추천 순위 등 방향성 파악에 더 무게를 두고 해석해야 합니다.
